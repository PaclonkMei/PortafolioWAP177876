ACTIVITY 19 // LOS PRIMEROS MINUTOS CUENTAN

THE FIRST
MINUTES COUNT

La actividad documenta la recopilación inicial de información de un sistema operativo Linux en ejecución, simulando la intervención de un primer respondiente ante un posible incidente digital. Se consultan datos del sistema, sesiones, procesos, servicios, conexiones, configuración de red, registros y archivos relevantes para preservar información volátil y orientar el análisis posterior.

IMPLEMENTACIÓN: la práctica se desarrolló desde Linux Mint. Los comandos utilizados corresponden a herramientas nativas del entorno Linux y se documentan como equivalentes funcionales a las utilidades de Windows indicadas en la guía.

LIVE FORENSIC TRIAGE
OBJECTIVE // 01

Primer respondiente

Obtener una primera vista del estado del equipo sin apagarlo, considerando que parte de la información disponible puede ser volátil y cambiar durante la intervención.

SYSTEM STATE // 02

Estado del sistema

Consultar procesos, servicios, usuarios, tareas programadas, características del equipo y registros del sistema para identificar actividad que requiera revisión.

NETWORK STATE // 03

Actividad de red

Examinar interfaces, conexiones, vecinos de red, perfiles inalámbricos y configuración de resolución de nombres, interpretando cada fuente según su alcance.

OUTPUT // 04

Registro y preservación

Guardar las salidas de comandos y el informe ejecutivo en el paquete de evidencias para facilitar su consulta y mantener trazabilidad del trabajo.

Las herramientas consultan fuentes distintas y no todas representan un historial completo. Por ejemplo, la tabla de vecinos refleja asociaciones almacenadas recientemente, mientras que la configuración DNS no equivale a un historial de dominios visitados.

06 // FORENSIC TAKEAWAY

VOLATILITY + CONTEXT + TRACEABILITY
19

Los primeros minutos ayudan a preservar el contexto del incidente.

La recopilación inicial permite registrar el estado observable del sistema antes de que cambie: sesiones, procesos, servicios, conexiones y registros. Sin embargo, cada fuente tiene límites; una tabla de vecinos no representa todas las comunicaciones, la configuración DNS no equivale al historial de navegación y las marcas de tiempo deben interpretarse según su disponibilidad y significado. Por ello, los resultados deben conservarse junto con el procedimiento y el informe ejecutivo, sin atribuirles conclusiones que no respalden.

Las salidas TXT y el informe se incorporan desde la carpeta de evidencias indicada en esta página. Las capturas y el documento académico complementan el registro de la actividad.
