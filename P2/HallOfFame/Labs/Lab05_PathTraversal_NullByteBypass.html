File path traversal, validation of file extension with null byte bypass

Laboratorio de PortSwigger Web Security Academy resuelto dentro del entorno autorizado. 01 // LAB OBJECTIVE

VULNERABILITY CONTEXT

El objetivo del laboratorio consiste en recuperar el contenido de /etc/passwd desde el endpoint que carga las imágenes de producto. En este caso, la aplicación valida que el nombre recibido mediante filename termine con la extensión de imagen esperada, por lo que una ruta de traversal directa hacia el archivo objetivo no supera la comprobación.

El bypass aprovecha una discrepancia entre la validación de la cadena y el procesamiento posterior de la ruta. Conservamos la terminación esperada por la aplicación, pero colocamos antes de ella el marcador de terminación correspondiente. Para mantener esta documentación compatible, la representación codificada se señala como ../../../etc/passwd%00.png.

VULNERABILITY SIGNAL ../../../etc/passwd%00.png EXPECTED RESULT // LOCAL FILE CONTENT

02 // RESOLUTION PATH

OFFICIAL 3-STEP FLOW
  1. 01

    Usamos Burp Suite para interceptar e identificar una petición que obtiene una imagen de producto mediante el parámetro filename.

  2. 02

    Enviamos la solicitud a Repeater y sustituimos el valor original por una ruta de traversal hacia /etc/passwd, seguida de ../../../etc/passwd%00.png y la extensión .jpg que la aplicación espera validar.

  3. 03

    Reenviamos la petición y comprobamos que la respuesta contiene el contenido de /etc/passwd, confirmando que la validación de extensión fue superada dentro del laboratorio.

03 // EVIDENCE RUN

BURP SUITE CAPTURES
STEP_01 // DISCOVERY

Localizamos una solicitud de imagen válida

Desde Proxy → HTTP history identificamos una petición GET al endpoint /image. El parámetro filename contiene un archivo de imagen válido con la extensión esperada, lo que nos permite observar la estructura normal de la solicitud antes de modificarla.

STEP_02-03 // NULL BYTE BYPASS

Modificamos el parámetro y obtenemos el archivo objetivo

En Repeater sustituimos el valor original por una ruta de traversal hacia /etc/passwd. Después del nombre del archivo objetivo colocamos ../../../etc/passwd%00.png y mantenemos .jpg al final de la cadena para satisfacer la validación de extensión presente en el laboratorio.

MODIFIED REQUEST GET /image?filename=../../../../etc/passwd%00.png HTTP/1.1

04 // TECHNICAL ANALYSIS

WHY THE BYPASS WORKS
01

Validación centrada en la extensión

La aplicación comprueba que la cadena proporcionada finalice con la extensión de imagen esperada, pero esa condición por sí sola no garantiza que el archivo procesado sea realmente una imagen permitida.

02

Interpretación diferente de la ruta

El laboratorio demuestra una discrepancia entre la validación inicial del valor y la forma en que una capa posterior interpreta la terminación del nombre de archivo.

03

Impacto

Una validación insuficiente puede permitir la lectura de archivos locales accesibles para el proceso web, incluyendo información sensible del sistema o de la aplicación.

04

Mitigación

Conviene evitar que rutas controladas por el usuario lleguen directamente a operaciones del sistema de archivos; cuando sea necesario, se deben usar valores permitidos, canonicalizar la ruta y comprobar que el destino final permanezca dentro del directorio autorizado.
