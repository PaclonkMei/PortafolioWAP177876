01 // LAB OBJECTIVE

VULNERABILITY CONTEXT

El objetivo consiste en recuperar el contenido de /etc/passwd desde el endpoint utilizado para cargar imágenes de producto. La aplicación intenta impedir el recorrido de directorios mediante un filtro que rechaza las secuencias de traversal visibles en la entrada.

La debilidad aparece porque el valor se vuelve a decodificar después de esa validación. Al enviar la secuencia peligrosa con una capa adicional de codificación, el filtro no observa directamente el traversal y una etapa posterior de decodificación reconstruye la ruta antes de que el servidor la utilice.

VULNERABILITY SIGNAL ..%252f..%252f..%252fetc/passwd EXPECTED RESULT // LOCAL FILE CONTENT

02 // RESOLUTION PATH

OFFICIAL 3-STEP FLOW
  1. 01

    Usamos Burp Suite para interceptar e identificar una petición que solicita una imagen de producto.

  2. 02

    Enviamos la solicitud a Repeater y modificamos el parámetro filename con ..%252f..%252f..%252fetc/passwd, aplicando la capa de codificación necesaria para atravesar la validación.

  3. 03

    Enviamos la petición modificada y verificamos que la respuesta contiene el archivo /etc/passwd, confirmando el bypass.

03 // EVIDENCE RUN

BURP SUITE CAPTURES
STEP_01 // DISCOVERY

Identificamos la petición de imagen

Desde Proxy → HTTP history localizamos una solicitud GET al endpoint /image. La petición seleccionada utiliza filename=61.jpg, confirmando que el recurso solicitado se controla mediante el parámetro filename.

STEP_02A // FIRST ENCODED ATTEMPT

Probamos la representación codificada en Repeater

Tras enviar la petición a Repeater, sustituimos el nombre de la imagen por una representación codificada del recorrido hacia el archivo objetivo. En este punto el servidor responde con 400 Bad Request y el mensaje No such file, por lo que todavía no alcanzamos la interpretación requerida por la aplicación.

STEP_02B // EXTRA ENCODING LAYER

Aplicamos una segunda capa de URL-encoding

Seleccionamos el valor del parámetro y utilizamos la función de Burp Convert selection → URL → URL-encode all characters. Esta operación añade la capa extra de codificación necesaria para que la entrada supere el filtro inicial y sea reconstruida por la decodificación posterior de la aplicación.

ENCODED VALUE ..%252f..%252f..%252fetc/passwd
STEP_03 // BYPASS CONFIRMED

La decodificación adicional reconstruye el traversal

Reenviamos la solicitud con la nueva representación. La aplicación responde con HTTP/1.1 200 OK y el cuerpo contiene entradas de /etc/passwd, demostrando que el filtro se ejecuta antes de la transformación que reconstruye la ruta peligrosa.

MODIFIED REQUEST GET /image?filename=..%252f..%252f..%252fetc/passwd HTTP/1.1

04 // TECHNICAL ANALYSIS

WHY THE BYPASS WORKS
01

Validación antes de normalizar

El control inspecciona una representación de la entrada antes de que todas las transformaciones y decodificaciones hayan terminado.

02

Decodificación adicional

Una capa extra de URL-encoding oculta temporalmente los caracteres de traversal. La decodificación posterior vuelve a convertirlos en una ruta funcional.

03

Impacto

El comportamiento permite escapar del directorio destinado a imágenes y leer archivos locales accesibles para el proceso web.

04

Mitigación

La aplicación debe decodificar y canonicalizar la entrada antes de validarla, usar nombres o identificadores permitidos y comprobar que la ruta final permanezca dentro del directorio autorizado.
