01 // LAB OBJECTIVE

VULNERABILITY CONTEXT

El objetivo consiste en demostrar que una validación enfocada únicamente en bloquear secuencias como ../ puede ser insuficiente. Si el backend utiliza directamente el valor proporcionado por el usuario y acepta rutas absolutas, todavía puede accederse a archivos fuera del directorio esperado.

La comprobación se realiza sobre el endpoint que entrega imágenes de producto. Al sustituir el nombre normal de una imagen por /etc/passwd, la respuesta devuelve el contenido de ese archivo local del servidor.

VULNERABILITY SIGNAL filename=/etc/passwd EXPECTED RESULT // LOCAL FILE CONTENT

02 // RESOLUTION PATH

OFFICIAL 3-STEP FLOW
  1. 01

    Usamos Burp Suite para interceptar e identificar una petición que obtiene una imagen de producto.

  2. 02

    Modificamos el parámetro filename y asignamos el valor absoluto /etc/passwd.

  3. 03

    Enviamos la petición y comprobamos que la respuesta contiene el contenido del archivo /etc/passwd.

03 // EVIDENCE RUN

BURP SUITE CAPTURES
STEP_01 // DISCOVERY

Localizamos la petición de imagen

En Proxy → HTTP history identificamos solicitudes GET al endpoint /image. La petición seleccionada utiliza un valor normal como filename=45.jpg, confirmando que el servidor recibe el nombre del archivo mediante un parámetro controlable.

STEP_01B // BASELINE

Enviamos la petición a Repeater

Antes de alterar el parámetro verificamos el comportamiento base en Repeater. La solicitud con filename=45.jpg devuelve HTTP/1.1 200 OK y datos JPEG, por lo que tenemos una referencia clara para comparar la modificación.

STEP_02-03 // BYPASS

Sustituimos el nombre por una ruta absoluta

Modificamos el parámetro a filename=/etc/passwd y reenviamos la petición. La aplicación responde con estado 200 OK y muestra entradas del archivo de usuarios del sistema, demostrando lectura arbitraria de archivo mediante ruta absoluta.

MODIFIED REQUEST GET /image?filename=/etc/passwd HTTP/1.1

04 // TECHNICAL ANALYSIS

WHY THE BYPASS WORKS
01

Filtro incompleto

El control bloquea secuencias de traversal, pero no impide que el usuario especifique una ruta absoluta.

02

Entrada controlable

El valor de filename llega al mecanismo que selecciona archivos en el servidor.

03

Impacto

Un atacante puede leer archivos locales accesibles para el proceso web, exponiendo información sensible del sistema.

04

Mitigación

La aplicación debe usar identificadores seguros o nombres permitidos, normalizar rutas y verificar que el archivo resuelto permanezca dentro de un directorio autorizado.
