01 // LAB OBJECTIVE

VULNERABILITY CONTEXT

El objetivo es recuperar el contenido de /etc/passwd desde un endpoint que carga imágenes. La aplicación intenta protegerse eliminando las secuencias ../ proporcionadas por el usuario antes de utilizar el valor de filename.

El problema es que la eliminación ocurre una sola vez. Al utilizar secuencias anidadas como ....//, el filtro elimina la parte interna y deja nuevamente una secuencia válida ../, permitiendo reconstruir el recorrido hacia directorios superiores.

VULNERABILITY SIGNAL ....//....//....//etc/passwd EXPECTED RESULT // LOCAL FILE CONTENT

02 // RESOLUTION PATH

OFFICIAL 3-STEP FLOW
  1. 01

    Usamos Burp Suite para interceptar e identificar una petición que solicita una imagen de producto.

  2. 02

    Enviamos la petición a Repeater y modificamos filename con el valor ....//....//....//etc/passwd.

  3. 03

    Enviamos la petición modificada y comprobamos que la respuesta contiene el contenido del archivo /etc/passwd.

03 // EVIDENCE RUN

BURP SUITE CAPTURES
STEP_01 // DISCOVERY

Identificamos la petición de imagen

Desde Proxy → HTTP history localizamos una solicitud GET al endpoint /image. La petición seleccionada usa un valor normal como filename=20.jpg, lo que confirma que el nombre del archivo llega al servidor mediante un parámetro controlable.

STEP_02-03 // FILTER BYPASS

Usamos traversal anidado contra el filtro no recursivo

En Repeater reemplazamos el valor por ....//....//....//etc/passwd. La respuesta devuelve HTTP/1.1 200 OK y contiene las entradas de /etc/passwd, demostrando que el filtrado no recursivo puede ser evadido.

04 // TECHNICAL ANALYSIS

WHY THE BYPASS WORKS
01

Sanitización de una sola pasada

La aplicación elimina patrones ../, pero no vuelve a procesar el resultado después de la transformación.

02

Secuencia anidada

El patrón ....// contiene una secuencia ../ interna. Al retirarla una vez, el texto restante vuelve a formar ../.

03

Impacto

El atacante puede escapar del directorio destinado a imágenes y leer archivos locales accesibles para el proceso de la aplicación.

04

Mitigación

No se debe confiar en reemplazos de cadenas aislados. Conviene usar identificadores seguros, normalizar/canonicalizar rutas y verificar que la ruta final permanezca dentro del directorio permitido.
